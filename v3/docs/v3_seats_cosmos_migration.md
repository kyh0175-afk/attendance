# v3 좌석·코스모스 명단 이식 설계 (2026-08-11 정찰 — 사자님 지시: v2 은퇴 전 v3 구현)

## 왜
v2 은퇴(9월 초) 결정과 "좌석·코스모스 관리는 v2 잔류"가 상충 → **v3 admin에 이식해야 v2를 완전히 끌 수 있다.**

## 이식 원칙

1. **DB 무변경(additive만)** — v2와 같은 테이블·RPC를 그대로 읽어 병행 기간 양쪽 동작.
2. **인증은 v3 체계로** — v2는 anon 접근 의존. v3판은 `authenticated + is_staff()` 게이트로 접근하도록 **RLS 정책 추가**(anon 정책은 건드리지 않음 → v2 병행 무간섭). 9월 은퇴 시 `anon_policy_harden.sql` 섹션 4 실행해도 v3판이 살아 있는지가 완료 조건.
3. **UI는 v3 문법** — admin.html 5탭에 `좌석`·`코스모스` 2탭 추가, v3 토큰(에스프레소/램프)·기존 표 패턴 준수. v2 코드는 참조하되 복붙 금지(v2는 anon sb 패턴·이모지 UI).
4. 학생 좌석 신청 뷰: **결정 필요** — v3 학생 PWA에 넣을지(신청 기간에만 카드 노출 권장) / 신청은 계속 별도 창구로 할지.

## 완료 기준 (이게 검증되면 끝)

1. v3 admin에서: 신청 기간 생성 → 학생 신청 조회 → 배치 편집·저장 왕복이 라이브 DB에서 동작
2. 코스모스 탭: 월 선택 → 명단·충돌 목록이 v2 탭8과 동일 데이터로 표시
3. **RLS 리허설**: anon 키로 좌석 테이블 접근이 (은퇴 SQL 적용 가정 하에) 막혀도 v3 admin은 동작 — 사전 시뮬레이션 쿼리로 검증
4. v2 병행 무간섭: v2 좌석·코스모스 탭 기존 동작 그대로 (스모크)
5. pytest 없음(정적 앱) → 대신 라이브 스모크 체크리스트 첨부하여 전 항목 통과
